# Trancy 桌面双语字幕

Windows / PyQt6 桌面应用：一个设置窗口，一层可在整个桌面自由拖动的中英字幕。语音识别使用本机 SubtitleService，翻译沿用插件的引擎。中文原文配英文译文，英文原文配中文译文。

| 来源 | 获取方式 | 字幕同步方式 |
| --- | --- | --- |
| 系统声音 | WASAPI 环回捕获所选扬声器／耳机的系统混音，连续分段识别 | 新字幕随识别、翻译结果更新 |
| PotPlayer | 读取正在播放的本地文件，交给 SubtitleService 识别 | 跟随 PotPlayer 的播放位置、暂停和倍速 |
| B 站 | 扩展报告 BV、CID、分 P 和播放状态，桌面下载当前视频音轨 | 跟随发起任务的浏览器标签页 |
| YouTube | 扩展报告视频 ID 和播放状态，使用网页音轨或 yt-dlp 获取音频 | 跟随发起任务的浏览器标签页 |

本地播放器仅适配 **PotPlayer**。其他应用发出的声音仍可以由“系统声音”模式捕获，但没有为其他播放器实现文件发现或时间轴同步。

## 启动与依赖

当前版本是可以直接运行的 Python 桌面程序，入口是 [app.py](app.py)。

- 日常启动：双击 [启动桌面字幕.vbs](启动桌面字幕.vbs)，显示设置窗口而不显示控制台。
- 查看启动错误：双击 [启动桌面字幕.cmd](启动桌面字幕.cmd)。
- 启动诊断日志：`desktop/data/logs/desktop.log`。

启动器优先使用 `desktop/.venv/Scripts/` 下的独立解释器；没有该环境时，使用当前电脑已有的 `D:\ProjectsPycharm\MultiProjects\.venv\Scripts\pythonw.exe`／`python.exe`。

在新电脑安装桌面界面依赖，可在 `desktop` 目录执行：

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -B app.py
```

[requirements.txt](requirements.txt) 包含 PyQt6、NumPy、Requests、PyAudioWPatch 和 Send2Trash。界面环境不需要再安装一份 Whisper、PyTorch 或 yt-dlp；识别和网页音频处理使用下面的共享环境。

默认 SubtitleService 目录为 `D:\dev\SubtitleService`。可以在设置窗口右侧选择实际引擎目录。需要已有：

| 文件或目录 | 用途 |
| --- | --- |
| `.venv/Scripts/python.exe` | Whisper 识别、B 站音频适配、yt-dlp、PyAV |
| `service/engine.py` | 共用识别入口 |
| `models/whisper` | Whisper Small／Large v3 模型 |
| `runtimes/qwen3/Scripts/python.exe` | 选择 Qwen3-ASR 时使用的独立解释器 |
| `models/qwen3` | Qwen3-ASR 与时间轴对齐模型 |

共享服务的完整安装、模型下载和 GPU 依赖按该目录原有 README 操作。桌面程序复用这些模型文件与识别代码，并启动自己拥有的驻留识别进程；同一模型和计算设备的连续任务可以复用已经加载的权重。这里不表示与另一款正在运行的应用共用同一个 Python 进程。

桌面程序不需要先启动 SubtitleService 的 `18765` HTTP 服务，也不会修改它的接口、模型文件或其他应用的识别进程。

## 系统声音实时字幕

1. 在“识别与翻译”中选择模型、计算设备和翻译引擎。
2. 打开“系统声音”，选择实际正在输出声音的设备。
3. 点击“开始实时双语字幕”。
4. 点击“停止当前任务”结束捕获和当前处理。

默认每 **4 秒**形成一段音频，可在界面调整为 2–12 秒。字幕延迟包含收集这一段声音、语音识别和翻译耗时；首次加载模型还会增加等待。它是持续分段处理，尚未宣称达到零延迟或某个固定的端到端延迟。

捕获来源是所选输出设备的 WASAPI 环回，包含该设备上各应用的混音。如果声音从另一张声卡或蓝牙耳机播放，需要选择那个设备。设备刷新和开始捕获时均检查它是否为环回设备，不会在失败时自动切换成麦克风。

识别速度持续跟不上声音时，界面会提示积压，并限制等待队列，避免旧声音无限堆积。可以选择 Small 模型、使用可用的 NVIDIA GPU，或调大分段长度。静音片段会跳过保存和识别，识别模型继续负责语音活动检测。

## PotPlayer

1. 在 PotPlayer 中播放一个本地视频，或点击桌面程序中的“选择视频并用 PotPlayer 播放”。
2. 确认“PotPlayer”页显示了当前文件和进度。
3. 点击“生成当前视频双语字幕”。

程序通过 PotPlayer 的 Win32 消息接口读取文件名、播放位置、总时长、暂停状态和速度。生成任务读取原视频中的音轨，不需要等待视频从头播放完；原视频文件保留。

较旧的 PotPlayer 版本可能不返回文件名或倍速。程序会显示未取得的状态，不会用窗口标题猜测文件路径；可以通过“选择视频并用 PotPlayer 播放”明确指定文件。未找到播放器时，可安装 PotPlayer，或设置环境变量 `TRANCY_POTPLAYER_EXE` 为其可执行文件路径。

“开始后，自动跟随 PotPlayer 切换的视频”决定已开始跟随时是否为下一条本地视频启动任务。取消勾选后，切换到其他视频不会继续显示旧视频字幕。

## B 站与 YouTube

网页模式需要**包含本次桌面桥代码的扩展副本**，仅安装原商店版还不会向桌面发送播放状态。

当前仓库根目录保留了打包插件的 `_metadata` 快照。请从独立的开发运行副本加载扩展，副本仅需要 `manifest.json`、`assets/`、`_locales/`、`index.html` 和 `popup.html`。不把根目录的 `_metadata`、`.git`、`desktop` 复制进去，也不删除原快照。Chromium 的元数据清理代码会删除保留的哈希文件，因此不应把原始快照目录直接作为加载测试目录。[Chromium 源码](https://chromium.googlesource.com/chromium/src/+/HEAD/extensions/common/file_util.cc#700)

双击 [生成浏览器扩展.cmd](生成浏览器扩展.cmd)，运行 [tools/prepare_extension.py](tools/prepare_extension.py) 生成 `desktop/data/unpacked-extension`。当前已生成这个运行副本。每次更新先准备完整的新副本，成功后将旧运行副本移入回收站，再切换到新副本；原始 `_metadata` 保留。

生成过程保留 `manifest.json` 的 `key`，扩展 ID 仍为 `mjdbhokoopacimoekfgkcoogikbfgngb`，桌面桥只接受这个扩展身份。

1. 启动桌面软件。
2. 在 Chrome 的 `chrome://extensions/` 打开开发者模式，通过“加载已解压的扩展程序”选择上述运行副本。
3. 后续代码更新后重新运行“生成浏览器扩展.cmd”，在扩展管理页点击“重新加载”，并刷新已经打开的视频网页。
4. 打开 B 站 BV 视频页面或 YouTube 视频页面，开始播放以准备当前视频元数据。
5. 在桌面软件“B 站 / YouTube”中选择对应视频，点击“生成所选网页视频双语字幕”。

浏览器桥仅监听 `127.0.0.1:18766`。它校验扩展 Origin、自定义请求头和会话标识，不提供任意网址代理、文件读写或命令执行接口。这里只传当前视频信息、播放状态、待翻译的文本与译文。浏览器 Cookie 不会导出；已取得的签名音轨地址只在内存与进程管道中临时传递，不写入设置、缓存或日志。

不同标签页分别绑定。B 站按 BV、CID 和分 P 区分任务，YouTube 按视频 ID 区分任务；迟到的旧页面报告、上一分 P 的取流响应、已经过期的播放状态不能继续用于当前字幕。广告期间暂停跟随内容字幕。首次生成必须点击按钮；“开始后，跟随所选标签页切换的视频”默认关闭，开启后才会随该标签页的后续视频启动任务。

音频获取过程：

- **B 站**：复用 `SubtitleService/service/bilibili.py`，请求当前 BV／CID 的播放音轨，补充网页中已捕获且 CID 匹配的地址；必要时尝试服务已有的解析器。
- **YouTube**：优先尝试当前播放器提供的独立音轨，缺失或失效时使用共享环境的 yt-dlp 解析。下载后使用 PyAV 检查音频可解码和基本时长，拒绝把一个短分片当成完整视频。

站点需要登录、音轨地址过期、签名解析失败或网络限制时，界面会显示失败。可以在原网页播放后重试，或使用系统声音模式。不会把接口返回成功但没有音频的情况显示为字幕生成成功。

## 翻译引擎与插件的关系

界面的两个选项分别是：

| 选项 | 实际行为 | 是否需要浏览器 |
| --- | --- | --- |
| Google · 插件内置引擎 | 使用当前插件内置 Google 实现相同的 `translate_a/t` 地址、表单批量请求、空白规范化和实体解码 | 不需要；需要网络访问翻译服务 |
| 浏览器插件当前引擎 | 请求扩展读取 `state.translatorService.subtitle`，调用插件已有的 `Cl.translate` 调度器 | 需要浏览器中已加载更新后的插件并与桌面连接 |

Google 模式是桌面的默认选项。插件模式跟随扩展当前选中的字幕翻译引擎，包括它已有的模型和鉴权配置。账号 token 和供应商 API key 只在扩展后台读取并交给现有翻译器，桌面软件不接收或保存这些凭据。插件模式切换引擎后重新生成即可使用新配置。

中英翻译方向根据识别语言和原文文字判断。模型返回中文时产生英文译文；返回英文时产生中文译文，字幕浮层显示原文与译文两行。

**浏览器原有的 YouTube 云端 AI 转录与本桌面软件的识别流程不同：** 原扩展将任务提交给 `api.trancy.org` 的 YouTube 转录接口；本桌面软件取得音频后，在本机调用 SubtitleService，再进行文本翻译。桌面程序没有将 B 站地址伪装成 YouTube 转录任务，也没有将本地视频上传到该 YouTube 接口。原扩展有字幕／无字幕的流程见[根 README](../README.md)。

## 桌面字幕、缓存与临时文件

- 字幕浮层独立置顶，解锁后可以拖到任意显示器上的合适位置。
- “锁定位置，鼠标可穿透字幕”用于固定位置后操作下面的播放器。
- 可分别调整原文和译文字号、颜色、整体宽度及背景不透明度。
- 设置窗口可以最小化；托盘菜单可再次打开设置或退出。
- 设置、字幕缓存、临时文件和日志位于 `desktop/data/`，已经排除在 Git 提交范围之外。
- 临时录音、下载音轨和任务临时目录由本程序按任务范围回收，删除操作只进入 Windows 回收站。回收失败会保留文件并提示，不永久删除兜底。
- 本地原视频、用户下载目录、共享模型和服务设置不属于临时文件清理范围。

翻译失败时，已经识别的原文仍可查看。点击“重试未完成翻译”可补译；没有把错误提示当作译文写入双语字幕。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 双击没有出现窗口 | 用 `.cmd` 启动器查看错误，检查桌面 Python 依赖和 `desktop/data/logs/desktop.log` |
| 找不到输出设备或没有声音电平 | 点击设备“刷新”，选择实际发声的扬声器／耳机；检查它的 WASAPI 环回支持 |
| 模型加载失败 | 检查设置中的 SubtitleService 路径、所选模型及其解释器；GPU 不可用时可显式选择 CPU |
| 无法取得 PotPlayer 文件 | 使用“选择视频并用 PotPlayer 播放”；检查播放器是否支持当前消息接口 |
| 浏览器一直没有连接 | 确认加载的是包含桌面桥的运行副本，重新加载扩展并刷新视频页；检查是否另一个桌面实例占用 18766 |
| B 站提示 CID 尚未就绪 | 在当前分 P 网页开始播放，再点击生成 |
| 网页取音失败 | 在原页面播放后重试；登录或签名限制无法通过时使用系统声音模式 |
| Google 请求失败 | 检查网络，或选择浏览器中已经配置好的字幕翻译引擎 |
| 插件模式超时 | 确认插件连接状态和当前字幕引擎可用；插件账号或 API key 仍在插件内配置 |
| 字幕突然变旧或不再同步 | 检查播放器是否切换视频、网页是否关闭或进入广告；选择正确来源重新生成 |
| 字幕挡住鼠标操作 | 勾选锁定和鼠标穿透，需移动时再解锁 |
