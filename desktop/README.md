# Trancy 桌面双语字幕

Windows / PyQt6 桌面应用：设置窗口与可在整个桌面自由拖动的中英字幕。只保留 **PotPlayer、B 站和 YouTube**，系统声音捕获与实时语音翻译已经移除。识别复用本机 SubtitleService；文字翻译继续使用 Google 或连接器当前引擎。

| 来源 | 有原字幕 | 无原字幕 | 同步 |
| --- | --- | --- | --- |
| PotPlayer | 优先读取同名 SRT／VTT／ASS／SSA，再尝试内嵌文本字幕 | 只识别当前播放位置附近的音频片段 | PotPlayer 文件、播放进度、暂停、倍速 |
| B 站 | 读取当前 BV、CID、分 P 的平台字幕 JSON | 获取对应音轨，再识别播放附近片段 | 发起任务的标签页与分 P |
| YouTube | 读取人工／平台自动字幕，保留可用的词时间轴与平台译文 | 获取视频音轨，再识别播放附近片段 | 发起任务的标签页与视频 ID |

本地播放器只适配 PotPlayer。正在进行的网页直播、图像字幕（PGS／VobSub）和只有画面中的硬字幕暂未专门适配。

## 启动与依赖

当前版本是可以直接运行的 Python 桌面程序，入口是 [app.py](app.py)。

- 日常启动：双击 [启动桌面字幕.vbs](启动桌面字幕.vbs)，显示设置窗口而不显示控制台。
- 查看启动错误：双击 [启动桌面字幕.cmd](启动桌面字幕.cmd)。
- 启动诊断日志：`desktop/data/logs/desktop.log`。

启动器优先使用 `desktop/.venv/Scripts/` 下的独立解释器；没有该环境时，使用当前电脑已有的 `D:\ProjectsPycharm\MultiProjects\.venv\Scripts\pythonw.exe`／`python.exe`。

在新电脑安装桌面界面依赖，可在 `desktop` 目录执行：

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -B app.py
```

[requirements.txt](requirements.txt) 包含 PyQt6、Requests 和 Send2Trash。界面环境不需要再安装一份 Whisper、PyTorch 或 yt-dlp；识别和网页音频处理使用下面的共享环境。

默认 SubtitleService 目录为 `D:\dev\SubtitleService`。可以在设置窗口右侧选择实际引擎目录。需要已有：

| 文件或目录 | 用途 |
| --- | --- |
| `.venv/Scripts/python.exe` | Whisper 识别、B 站音频适配、yt-dlp、PyAV |
| `service/engine.py` | 共用识别入口 |
| `models/whisper` | Whisper Small／Large v3 模型 |
| `runtimes/qwen3/Scripts/python.exe` | 选择 Qwen3-ASR 时使用的独立解释器 |
| `models/qwen3` | Qwen3-ASR 与时间轴对齐模型 |

共享服务的完整安装、模型下载和 GPU 依赖按该目录原有 README 操作。桌面程序复用这些模型文件与识别代码，并启动自己拥有的驻留识别进程；同一模型和计算设备的连续任务可以复用已经加载的权重。这里不表示与另一款正在运行的应用共用同一个 Python 进程。

桌面程序不需要先启动 SubtitleService 的 `18765` HTTP 服务，也不会修改它的接口、模型文件或其他应用的识别进程。

## 运行链路：参考原插件的字幕预取

```text
视频与当前播放位置
  → 读取现成字幕及时间轴
  → 有字幕：直接原文，不启动语音识别
  → 缺字幕：获取音频，只识别当前附近短窗口
  → 网页原字幕读取失败／超时：只重试原字幕，不自动进入语音识别
  → 复用已有译文与文本缓存
  → 首批最多 3 句，随后每批最多 30 句，向后预取最多 90 句
  → 返回即更新译文，按播放器时间显示桌面中英字幕
```

- 原字幕不要求整份译文先完成。翻译队列先保证当前句和随后少量句子，再准备后面的译文。
- Google 至多 4 个请求工作线程，预取至多占 2 个，给跳转后的当前字幕留出处理位置；请求之间共用 150 毫秒发送间隔，并复用 HTTP 连接。
- 已有中英字幕直接使用。相同文本的翻译按语种与引擎缓存，最终词对齐改变字幕边界时无需重新请求翻译。
- 跳转后取消旧位置尚未发送的翻译，优先新位置。已发送的网络请求完成后可作为缓存，但旧代次的错误和字幕不会覆盖当前画面。
- 网页只有明确返回没有可用字幕轨时才获取音频、启动本地识别。读取失败／超时自动重试原字幕一次，仍失败则提示“重试未完成字幕”，不会因此加载模型。已知存在字幕轨却未取得正文也属于读取失败。
- 网页刷新同一个视频，也按新的页面代次重新读取字幕。停止／换源取消未完成的原字幕请求和旧任务。

原插件普通浮层使用的 `drivePretranslate`／`pretranslate`／`Bf.mt` 在 [assets/edvideo-main.js](../assets/edvideo-main.js)。桌面沿用其播放位置优先和提前批量翻译策略，不再按整视频识别产出的顺序串行排队。原插件 B 站还有批量后台补全，但桌面采用有限预取，避免翻译远离播放位置的整片内容。

## 无字幕时的识别缓冲

首次窗口从播放位置前约 2 秒开始，最多 12 秒；后续窗口最多 20 秒。正常播放仅提前准备约 35 秒音频，暂停仅准备约 10 秒。短小的新增空档会合并后再处理，避免每移动一点就启动一次识别。缓冲充足时不再调用模型。

PyAV 先 seek，再解码指定窗口，避免跳转到影片后段后重新解码开头。原文和词时间戳同时加回窗口起点，与播放器秒制时间轴一致。空白片段也记录已处理范围，避免反复识别静音。跳转到未处理位置时优先识别新窗口；已处理范围仍可复用。

网页没有字幕时，当前仍需要先取得并验证音轨文件，然后进行上述短窗识别；尚未实现网络音频边下载边识别。首次模型加载、原字幕访问、下载、识别和文字翻译均可能增加等待，不承诺固定延迟或某个 CPU 降幅。

## PotPlayer

1. 在 PotPlayer 中播放本地视频，或点击“选择视频并用 PotPlayer 播放”。
2. 确认文件和进度正确，点击“生成当前视频双语字幕”。
3. 程序先读取现成字幕；没有文本字幕时才调用所选 SubtitleService 模型。

同名外挂字幕支持 UTF-8、UTF-16 和 GB18030。中英两轨按时间交叠匹配，不要求行数或分句相同。内嵌文本轨使用 FFprobe／FFmpeg（如果已有），否则使用 SubtitleService 环境的轻量 PyAV 子进程；读取字幕不会加载 Whisper 或 Qwen。

通过 Win32 消息接口读取 PotPlayer 的文件、位置、总时长、暂停和速度。较旧版本可能不返回文件名；程序不会从标题猜路径。可以使用“选择视频并用 PotPlayer 播放”明确指定，或设置 `TRANCY_POTPLAYER_EXE`。开启自动跟随后，切换文件才会自动开始新字幕任务。

## B 站与 YouTube

网页模式需要独立的 **Trancy 桌面字幕连接器** 扩展。它与原 Trancy 使用不同 ID，可以同时安装；网页端只注入桌面连接脚本，避免两个扩展同时绘制网页字幕浮层。

当前仓库根目录保留了打包插件的 `_metadata` 快照。请从独立的开发运行副本加载扩展，副本仅需要 `manifest.json`、`assets/`、`_locales/`、`index.html` 和 `popup.html`。不把根目录的 `_metadata`、`.git`、`desktop` 复制进去，也不删除原快照。Chromium 的元数据清理代码会删除保留的哈希文件，因此不应把原始快照目录直接作为加载测试目录。[Chromium 源码](https://chromium.googlesource.com/chromium/src/+/HEAD/extensions/common/file_util.cc#700)

双击 [生成浏览器扩展.cmd](生成浏览器扩展.cmd)，运行 [tools/prepare_extension.py](tools/prepare_extension.py) 生成 `desktop/data/desktop-connector`。每次更新先准备完整的新副本，成功后将旧连接器运行副本移入回收站，再切换到新副本；原始 `_metadata` 和以前的 `unpacked-extension` 副本保留。

连接器的独立 manifest 保存在 [browser-extension/manifest.json](browser-extension/manifest.json)，名称为 **Trancy 桌面字幕连接器**，固定 ID 为 `phkekicmpkiinghhklcoanjjdnccdeod`。每次重新生成副本都保留这个新 ID，桌面桥只接受它。原 Trancy 的 ID `mjdbhokoopacimoekfgkcoogikbfgngb` 不参与桌面任务。

1. 启动桌面软件。由以前同 ID 的版本切换到独立连接器时，先关闭并重新启动桌面软件，以使用新的扩展身份校验。
2. 在 Chrome 的 `chrome://extensions/` 打开开发者模式，通过“加载已解压的扩展程序”选择 `desktop/data/desktop-connector`。列表中会显示独立的“Trancy 桌面字幕连接器”卡片。
3. 后续代码更新后重新运行“生成浏览器扩展.cmd”，在扩展管理页点击“重新加载”，并刷新已经打开的视频网页。
4. 打开 B 站 BV 视频页面或 YouTube 视频页面，开始播放以准备当前视频元数据。
5. 在桌面软件“B 站 / YouTube”中选择对应视频，点击“生成所选网页视频双语字幕”。

浏览器桥仅监听 `127.0.0.1:18766`。它校验扩展 Origin、自定义请求头和会话标识，不提供任意网址代理、文件读写或命令执行接口。这里只传当前视频信息、播放状态、现成字幕正文与时间轴、待翻译的文本与译文。浏览器 Cookie 不会导出；已取得的签名音轨地址只在内存与进程管道中临时传递，不写入设置、缓存或日志。

不同标签页分别绑定。B 站按 BV、CID 和分 P 区分任务，YouTube 按视频 ID 区分任务；迟到的旧页面报告、上一分 P 的取流响应、已经过期的播放状态不能继续用于当前字幕。广告期间暂停跟随内容字幕。首次生成必须点击按钮；“开始后，跟随所选标签页切换的视频”默认关闭，开启后才会随该标签页的后续视频启动任务。

优先原字幕：B 站在网页上下文读取当前字幕轨及正文；YouTube 优先人工字幕，再使用平台自动字幕，并复用已捕获的原生字幕请求参数。可用的另一语言字幕作为现成译文，获取失败不会阻塞原字幕进入 Google 预取。只有网站确认没有可用原字幕时，才启动以下音频获取过程：

连接器 **0.1.3** 补上 B 站播放器元数据 `aid` 参数的识别，并复用当前 BV／分 P／CID 已加载的字幕正文，避免原网页已经显示字幕却仍重复下载。原字幕请求失败／超时不会触发音轨下载或模型加载。更新后需要重新加载连接器、刷新视频网页并重启桌面应用，旧进程和已注入的旧脚本不会自动更新。

旧连接器 0.1.1 没有原字幕请求通道，只能上报视频信息、处理文本翻译；新版桌面等待不到原字幕结果后，旧回退逻辑会加载识别模型。扩展卡片显示 0.1.1 时，需要重新加载到 0.1.3，不能只重启桌面应用。

0.1.3 同时恢复后台需要的 `commands` manifest 声明，修复 `reading 'onCommand'` 和 `reading 'getAll'` 启动错误。命令保留描述，不设置默认快捷键；Chrome 的 Commands API 需要声明 `commands`，默认键位可以省略。[Chrome 官方文档](https://developer.chrome.com/docs/extensions/reference/api/commands)

- **B 站**：复用 `SubtitleService/service/bilibili.py`，请求当前 BV／CID 的播放音轨，补充网页中已捕获且 CID 匹配的地址；必要时尝试服务已有的解析器。
- **YouTube**：优先尝试当前播放器提供的独立音轨，缺失或失效时使用共享环境的 yt-dlp 解析。下载后使用 PyAV 检查音频可解码和基本时长，拒绝把一个短分片当成完整视频。

站点需要登录、音轨地址过期、签名解析失败或网络限制时，界面会显示失败。可以在原网页播放后重试。不会把接口返回成功但没有音频的情况显示为字幕生成成功。

## 翻译引擎与插件的关系

界面的两个选项分别是：

| 选项 | 实际行为 | 是否需要浏览器 |
| --- | --- | --- |
| Google · 插件内置引擎 | 使用当前插件内置 Google 实现相同的 `translate_a/t` 地址、表单批量请求、空白规范化和实体解码 | 不需要；需要网络访问翻译服务 |
| 浏览器插件当前引擎 | 请求扩展读取 `state.translatorService.subtitle`，调用插件已有的 `Cl.translate` 调度器 | 需要浏览器中已加载更新后的插件并与桌面连接 |

Google 模式是桌面的默认选项。插件模式跟随连接器扩展当前选中的字幕翻译引擎，包括它已有的模型和鉴权配置。新 ID 拥有独立的浏览器扩展设置；原 Trancy 的账号或翻译配置不会自动转移，插件模式需要在连接器的设置界面中配置，Google 模式无需迁移账号。账号 token 和供应商 API key 只在扩展后台读取并交给现有翻译器，桌面软件不接收或保存这些凭据。

中英翻译方向根据识别语言和原文文字判断。模型返回中文时产生英文译文；返回英文时产生中文译文，字幕浮层显示原文与译文两行。

**浏览器原有的 YouTube 云端 AI 转录与本桌面软件的识别流程不同：** 原扩展将任务提交给 `api.trancy.org` 的 YouTube 转录接口；本桌面软件优先读取原字幕；没有原字幕时取得音频，在本机调用 SubtitleService 识别播放附近窗口，再进行文本翻译。桌面程序没有将 B 站地址伪装成 YouTube 转录任务，也没有将本地视频上传到该 YouTube 接口。原扩展有字幕／无字幕的流程见[根 README](../README.md)。

## 桌面字幕、缓存与临时文件

- 字幕浮层独立置顶，解锁后可以拖到任意显示器上的合适位置。
- “锁定位置，鼠标可穿透字幕”用于固定位置后操作下面的播放器。
- 默认**英文在上、中文在下**，英文 30 号、中文 24 号。中文语音的英文译文也放在上面；字号和颜色始终按语言设置。
- “字幕顺序”可以选择英文在上、中文在上、原文在上或译文在上，修改后立即作用于当前浮层并保存。
- 可分别调整英文字号、中文字号和颜色，以及整体宽度、背景不透明度。
- 默认启用“英文逐词点亮”：句子先以约 55% 亮度显示，进度到达某个词后该词及前面词累计亮起，亮度切换有约 0.12 秒过渡；未读词亮度可调，也可以关闭逐词点亮。
- 点亮始终形成从句首开始的连续亮色前缀，只有紧接着的一个词渐亮，后面保持暗色。绘制复用文本布局并采用互斥裁剪，避免 Qt 逐词选择范围造成隔词点亮；重复词、缩写、标点、emoji 和换行均经过逐词像素验证。小幅时钟抖动和同句词轴更新不会反复调暗已亮词，向后跳转仍可按新位置重算。
- 与原插件一致，只点亮英文主字幕，中文辅助字幕保持静态显示。Whisper／Qwen 返回的真实词时间轴用于英文原文；英文是译文或词时间轴缺失时，按句子时长均分有效词，属于估计，不表示译文有真实声学词对齐。
- PotPlayer 与网页模式用播放位置更新点亮，暂停不推进，向后跳转会重新调暗尚未播放的词。
- 设置窗口可以最小化；托盘菜单可再次打开设置或退出。
- 设置、字幕缓存、临时文件和日志位于 `desktop/data/`，已经排除在 Git 提交范围之外。
- 下载音轨和任务临时目录由本程序按任务范围回收，删除操作只进入 Windows 回收站。回收失败会保留文件并提示，不永久删除兜底。
- 本地原视频、用户下载目录、共享模型和服务设置不属于临时文件清理范围。

原文、已完成译文和识别范围可部分保存，不要求整片全部完成。下次访问时复用已处理部分；旧版完整缓存仍可读取且保留。外挂／网页字幕会重新确认当前原轨，逐句译文可按相同文本复用，避免旧字幕时间轴盖过更新后的字幕。

翻译失败时保留原文，并明确显示“翻译失败 · 点击重试”，不再无限显示“译文生成中”。点击“重试未完成字幕”只重试当前位置附近缺失的译文，也可以重启失败的短窗识别。

## 验证记录与当前边界

2026-10-13 的本轮验证包括原字幕优先、3／30／90 预译、跳转／页面代次隔离、部分缓存、暂停与广告期间不识别、词时间轴、关闭时等待任务与回收站清理。

当前 **185 项自动化检查全部通过**，包括英文逐词点亮的实际像素顺序、淡入词、播放时钟抖动和词轴更新回归；三个浏览器桥 JavaScript 文件通过语法检查。点亮修复的画面与逐词亮度记录在 `desktop/data/validation/word-follow-order/`。

完整 MainWindow 链路使用真实 SRT 读取器、受控播放位置和受控译文验证：100 条原字幕只预译当前窗口的 90 条，批次为 3／30／30／27；没有启动 ASR 进程，重启后复用已有译文。新版 Google HTTP 连接实现也实测通过了各 3 句的英文→中文与中文→英文请求。证据保存在 `desktop/data/validation/plugin-chain/`。

原字幕解析和短窗截取使用真实 PyAV 文本轨与生成音频验证；调度和浏览器 JS 使用受控响应。尚未将这些检查描述为用户日常 Chrome 中完整播放验收，也没有测得可承诺的 CPU 降幅。之前的 PotPlayer 实际同步和 Google 两方向请求检查保留在 `desktop/data/validation/` 与 [browser_verification.json](tests/browser_verification.json)，不代表本轮每种浏览器访问状态都已实测。

| 现象 | 处理 |
| --- | --- |
| 双击没有出现窗口 | 使用 `.cmd` 启动器检查 Python 依赖和 `desktop/data/logs/desktop.log` |
| 无法取得 PotPlayer 文件 | 使用“选择视频并用 PotPlayer 播放”，确认播放器支持文件接口 |
| 浏览器没有连接 | 确认独立连接器已加载，重新加载扩展并刷新视频页；检查是否另一桌面实例占用 18766 |
| 扩展报 `onCommand`／`getAll` 未定义 | 更新、重新加载 0.1.3 连接器；旧运行副本缺少后台依赖的 `commands` 声明 |
| B 站 CID 尚未就绪 | 在当前分 P 开始播放后重试 |
| 网页有字幕，却提示读取失败／超时 | 重新加载 0.1.3 连接器、刷新视频网页，点击“重试未完成字幕”；检查 `desktop/data/logs/desktop.log` 的 `caption_request`／`caption_result` |
| 无原字幕、网页取音失败 | 在已登录原网页播放后重试；检查站点访问和解析器版本 |
| Google 请求失败 | 检查网络，点击“重试未完成字幕”，或选择连接器已经配置好的引擎 |
| 缺字幕且模型启动失败 | 检查 SubtitleService、模型与解释器，修正后重试 |
| 字幕挡住鼠标操作 | 锁定并开启鼠标穿透；需要移动时解锁 |
